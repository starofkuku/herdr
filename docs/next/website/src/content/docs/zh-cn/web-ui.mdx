---

`herdr web` 将 Herdr 的终端 UI 提供给浏览器，并把浏览器的输入桥接回你的会话。它作为独立进程运行，不隶属于任何会话服务器，因此可以列出所有会话并让你选择。

这适用于通过 WireGuard 或 SSH 隧道等私有网络访问你自己的机器。它不是托管服务。

## 为什么是独立进程

每个 Herdr 会话都有自己的服务器，而会话服务器只知道自己那一个会话。只有位于它们之外的进程才能枚举全部会话并提供选择。`herdr web` 就是那个进程：一个监听器、一个端口、所有会话。

网关代理的是 CLI 使用的同一套 JSON API。浏览器不会以终端客户端身份接入，因此打开 Web UI 不会影响你终端窗格的布局或尺寸。

## 启用网关

除非配置了密钥，否则网关处于禁用状态。这是有意为之：开放的网关等同于远程 shell 访问，因此它绝不会在没有认证的情况下监听。

把密钥放进 `config.toml`，这样重启后依然有效：

```bash
key=$(head -c 32 /dev/urandom | base64)
```

```toml
[web]
key = "你生成的密钥"
```

```bash
chmod 600 ~/.config/herdr/config.toml
herdr web
```

没有密钥时，它会打印诊断信息并退出，而不是绑定端口。

密钥至少需要 16 个字符。它使用常量时间比较，并且永远不会写入日志。

由于 `config.toml` 中的密钥只和该文件一样私密，当文件可被其他用户读取时 Herdr 会拒绝启动，并提示执行 `chmod 600`。临时运行请改用 `HERDR_WEB_KEY`。

密钥至少需要 16 个字符。它使用常量时间比较，并且永远不会写入日志。

## 配置

```toml
[web]
# Address to listen on. Default: 127.0.0.1
bind = "127.0.0.1"
# TCP port. Default: 8787
port = 8787
# Directory containing the built web UI. Optional.
static_dir = "/home/you/herdr/web/dist"
# Optional Origin allowlist. Empty disables the check.
allowed_origins = []
# URL `herdr update web` downloads the page from. Optional.
update_url = "https://github.com/ogulcancelik/herdr/releases/download/web-ui/herdr-web-ui.html"
# Gateway key. Keep this file at chmod 600.
key = "..."
```

建议绑定私有接口而不是 `0.0.0.0`，这样端口只能从你预期的网络访问。

密钥来源按优先级顺序：

- `HERDR_WEB_KEY`
- `HERDR_WEB_KEY_FILE`，一个包含密钥的文件
- `config.toml` 中的 `[web] key`

基于文件的密钥不得被其他用户读取，Herdr 对 `config.toml` 和 `HERDR_WEB_KEY_FILE` 都会强制这一点。


## 提供 UI

网关在请求时从 `static_dir` 读取 UI；它永远不会被嵌入 herdr 二进制，因此你可以独立更新或替换它。未设置 `static_dir` 时，只提供 WebSocket 端点。

构建内置 UI：

```bash
cd web && bun install && bun run build
```

这会生成单个自包含的 `web/dist/index.html`。把 `static_dir` 指向该 `dist` 目录。

每个版本也会把同一个文件作为 `herdr-web-ui.html` 资产发布，因此你可以直接使用已发布的 UI，无需自行构建。

UI 独立于 herdr 二进制更新，因此还有一个始终保存最新构建的 `web-ui` 滚动发布：

```bash
mkdir -p ~/herdr-web
curl -fsSL -o ~/herdr-web/index.html \
  https://github.com/ogulcancelik/herdr/releases/download/web-ui/herdr-web-ui.html
```

把 `static_dir` 指向该目录。版本化发布的资产同名，步骤相同。

由于网关自己提供页面，页面与 WebSocket 同源，因此不需要额外的托管或 CORS 配置。

### 更新页面

页面是文件而不是二进制的一部分，因此单独更新：

```bash
herdr update web            # 下载并安装最新页面
herdr update web --check    # 只报告可用版本，不写入任何内容
```

这需要 `static_dir`（要有目录可写）和 `update_url`：

```toml
[web]
static_dir = "/home/you/herdr-web"
update_url = "https://github.com/ogulcancelik/herdr/releases/download/web-ui/herdr-web-ui.html"
```

下载内容会先写入临时文件，然后重命名覆盖 `index.html`，因此下载失败或中断不会让网关提供半个页面。看起来不像 herdr web UI 构建的文件（代理错误页、被截断的传输）会被拒绝而不是安装。

每个构建都在注释里带有版本号，`--check` 比较的就是它：

```html
<!-- herdr-web-ui version: 0.7.21 -->
```

当已安装页面和下载页面都带版本号时，版本相同即表示无需操作。更新后请在浏览器中刷新页面；网关每次请求都从磁盘读取该文件，因此无需重启。

不带子命令的 `herdr update` 更新的是二进制，不是页面。两者分别发布，互不更新。

### 发布页面

如果改动只涉及 UI，可以单独发布页面：

```bash
just web-publish
```

它会构建 `web/` 并把结果上传到 rolling 的 `web-ui` release（也就是 `update_url` 指向的位置）。不会创建 herdr 版本，也不会重新构建各平台二进制，因为它们都没有变化。

由于版本标记决定更新是否会被安装，仅前端的发布会默认打上一个不同的标记——`<crate 版本>+web.<时间戳>`，而不是单纯使用 crate 版本。若标记与已安装页面相同，`herdr update web` 会认为页面已是最新。也可以自己指定版本：

```bash
just web-publish 0.7.24
```

`just web-status` 会报告已安装的版本和上次构建的版本。

## 连接

在浏览器中打开网关地址，输入密钥，然后选择会话或输入新名称。

- 打开未运行的会话会启动它的服务器。
- 会话名可使用字母、数字、`.`、`_` 和 `-`。
- 多个客户端可以连接同一个会话并共享状态。

如果你保存了密钥,UI 还会记住你最后打开的会话,刷新页面后会直接回到该会话。用返回按钮主动离开会话会清除这一记忆,因此刷新后仍停留在选择页。

### 地址与刷新

你所在的界面会体现在 URL 中，因此刷新会停留在原处，而不是回到密钥表单：

```
#                      选择会话
#/<会话名>              该会话的 agent 列表
#/<会话名>/<窗格>       某个 agent 的对话
```

打开对话会新增一条历史记录，因此浏览器的后退和前进按钮可以在应用内导航。指向某个对话的链接可以分享或收藏；只要连接信息被记住，直接打开即可恢复。若没有保存密钥，则无处可重连，因此会先显示密钥表单。

### 连接中断

手机浏览器会挂起后台标签页，从而断开 WebSocket，因此回到页面时可能只看到一幅静止的旧画面，且没有任何提示。标题栏有一个小状态点：已连接时为绿色，重试中时呼吸闪烁，自动重试放弃后会变成一个可点击的 **重新连接**。重连会恢复会话及其订阅，因此后台标签页回到前台后能接着之前的进度。

## 界面

UI 是原生页面，而不是终端镜像。这里不渲染任何 ANSI；每个界面都由 JSON API 的数据构建。

**会话。** Herdr 已知的全部会话及其运行状态，另有一个输入框用于打开已有会话或启动新会话。

**Agent。** 所选会话中的 Agent，按工作区分组并显示各自当前状态。点击某个 Agent 即可打开。

**Agent 详情。** 单个 Agent 的最近输出、消息输入框，以及当 Agent 等待输入时出现的按键条（见下文）。

## Agent 控制台

输出是取自窗格的纯文本，因此在所有平台上都使用浏览器原生的滚动、选择和复制。

Agent 工作时，新输出会随产生而出现。滚动到顶部会逐页加载更早的输出，因此长对话可以回看而不必一次全部载入。没有更早内容时会显示 `start of history` 标记。

输入框用于向 Agent 发送消息。`Enter` 发送，`Shift+Enter` 换行。

发送消息后，只要 Agent 仍在处理该轮，发送按钮就会变成 **停止** 按钮。停止发送的是 Agent 自己声明用于中断的按键（通常是 `esc`），效果与自己按下该键相同。

本地 UI 状态（即你所在的界面和滚动位置）不与终端共享。只有 Agent 自身的输出和状态是共享的。

## 回答提示

当 Agent 阻塞等待输入时，输入框上方会出现 **waiting for you** 面板。根据 Agent 向 Herdr 上报的内容，该面板有两种形式。

### 选项（当 Agent 上报选项时）

使用结构化交互协议的 Agent 可以上报它正在等待的问题以及它提供的选项。此时面板会显示问题、每个选项的标签与说明，以及 **Send answer** 按钮；在这里做出的选择就是 Agent 提供的选项本身，而不是对其措辞的猜测。

会这样做的 Agent：

- **Codex** —— 安装 Herdr 集成后，对命令、文件和权限审批。
- **Claude Code** —— 对工具审批，机制相同。
- **Pi** —— 在安装 `@juicesharp/rpiv-ask-user-question` 插件后，对问卷。只有单问题对话框会出现；多问题对话框以及自定义回答的输入仍留在终端。

包含多个问题的请求会在一次调用中作答，因此 Agent 不会依据半截答案就开始行动。

Agent 的提示也会绘制到内嵌终端中，因此结构化面板与终端内容一致；面板只是更便于作答，在手机上尤其如此。即使 Agent 提供了结构化面板，依然可以在终端中完整作答，面板只是便利而非唯一途径。

#### 审批的时间窗口

审批是在 Agent 暂停、尚未显示自身提示时作答的，因此可作答的时间有限。若无人及时作答，问题会被撤回，Agent 会显示它通常的提示。因此终端用户不会一直等待一个没人在看的面板。可通过 Agent 环境中的 `HERDR_CODEX_PERMISSION_WAIT_MS` 或 `HERDR_CLAUDE_PERMISSION_WAIT_MS` 调整等待时长。

Pi 的问卷则不同：无论哪种途径，对话框都已在屏幕上等待，因此 Herdr 会提示更长时间（`HERDR_PI_ASK_WAIT_MS`，默认 120 秒）。该时间过后面板会被撤回，对话框保持原样。

### 按键（当 Agent 仅上报状态时）

对于不上报结构化请求的 Agent，面板会以文本显示窗格末尾内容，并提供 Agent 提示通常接受的按键：方向键、`Enter`、`Esc`、数字键以及 `y` / `n`。

该面板刻意不解析提示内容。它无法判断哪个选项对应哪一项，因此不去尝试；你阅读文本并按下按键，与在终端里完全一致。

这样做有两个原因：

- 它不会选错选项，因为它从不猜测选项的含义。
- 当 Agent 改变措辞时它依然可用，因为不对文本做任何匹配。

按键作为原始终端输入发送到窗格，因此行为与在终端中输入相同。在多数 Agent 中 `Esc` 是中止而非作答，因此它的样式与用于作答的按键区分开。

## 阅读对话

上报了原生会话文件的 Agent —— 即安装了 Herdr 集成的 pi、Claude Code 和 Codex —— 可以按结构化对话展示，而不是终端画面：每轮一次交互，工具调用可展开，并显示该会话的 token 数。

转录由服务端从 Agent 自己的会话日志解析，因此反映的是 Agent 记录的内容，而非其 TUI 恰好绘制的内容。窗格右键菜单可以复制指向该对话的深链接；参见 [codex-trace 链接](/docs/configuration/#codex-trace-links)。

每轮会显示回答和错误，Agent 的思考与工具调用则折叠在一个标签下，需要时可展开。思考通常比回答长得多，因此默认不占用版面。

Agent 工作时会轮询其转录。窗格输出增长时服务端并不发送事件——只有标题、元数据或诊断变化时才会——因此纯事件驱动的视图会在 Agent 开始书写的那一刻停止更新。轮询让最新的轮次随产生而出现，并在 Agent 离开工作状态后停止。

只上报会话 ID 的 Agent 和普通 shell 会回退为显示窗格画面。

### 在对话中跳转

转录旁边有一条窄轨，按顺序为你发送的每条消息显示一个刻度。你正在阅读的那一轮刻度会高亮，因此滚动时这条轨道同时也是位置指示器。

把鼠标移到刻度上会显示该条消息的内容，点击则把那一轮滚动到顶部。刻度保持为一个紧凑的居中区块，而不会铺满整个高度；当消息数超出可容纳数量时，会均匀采样——当前所在的刻度始终保留。

在触摸屏上，轨道悬浮在转录之上而不占用一列宽度，因此文字可以铺满整宽；闲置时它会淡成一条淡淡的提示。淡出状态下它不接收触摸，因此每一行开头都能正常选中和点击；触摸对话区域或滚动即可让它恢复清晰。触摸屏上不渲染标签，刻度会放大到便于点按的尺寸。触摸设备没有悬停状态，因此"仅悬停显示"的标签永远不会出现；改为点按刻度直接跳转。

手指还可以按住轨道的任意位置上下滑动来快速浏览各条消息，轨道旁会显示当前经过的那条消息预览，松手即跳转到该处。手机上的单个刻度是很小的目标，而且长对话经过采样后一个刻度往往代表多轮，因此滑动把整条轨道变成一个控件，而不要求精确点按。


## 主题

每个界面右上角都有主题切换。它在深色和浅色调色板之间切换，选择会记录在浏览器中。没有记录时，UI 跟随操作系统的 `prefers-color-scheme` 设置。

## 手机使用

布局是为窄屏设计的：Agent 卡片纵向堆叠，输入框停在键盘上方，提示按键按触摸尺寸设置。页面不是终端，因此没有视口尺寸需要协商，也不需要触发移动端布局模式 —— 它会像普通网页一样重排。

通知不会投递到浏览器。

## 远程访问

WireGuard 和 SSH 隧道是预期的访问方式。传输使用明文 `ws://`，因为隧道本身已经提供加密。

绑定到你的私有地址：

```toml
[web]
bind = "10.0.0.5"
```

或者保留默认的环回绑定，并通过 SSH 转发端口：

```bash
ssh -L 8787:127.0.0.1:8787 you@server
```

转发后的端口可通过 `ws://127.0.0.1:8787` 访问。不要把网关直接暴露到公网：密钥只是一个保护 shell 访问的静态秘密，不能替代隧道。

如果你把页面托管在网关之外的位置，请设置 `allowed_origins`，以免其他站点从浏览器连接你的网关。注意部分浏览器还会限制公网 HTTPS 页面访问私有网络地址。

## 分离

使用返回按钮离开会话；会话及其窗格会继续运行。关闭浏览器标签页会干净地分离，不会停止服务器。

要停止会话及其窗格，请使用 `herdr session stop <name>`。
